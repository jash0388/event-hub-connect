Daily stock work

Barcode labels, count sheets, and printing

Put a scannable code on the shelf and get the paper the day actually needs.

Puter·Product documentation·2 min read
On this page

  2. What the bars actually say

Print barcode labels

Select products and choose Labels, or use Label on a single product’s page. Pick a layout, choose what goes on the label, and print through your browser.

Label layouts
LayoutPage
Sheet of 30, Avery 5160US Letter, three across
Sheet of 21, Avery L7160A4, three across
Sheet of 10, Avery 5163US Letter, two across
Roll labels, 2.25 by 1.25 inOne label per page, for roll printers

A label can carry the name, the SKU, the price, the shelf code, and the barcode itself. Copies are either one per product, for shelf edges, or one per unit on hand, for labelling items; a measured product gets one label either way.

What the bars actually say

Labels encode the product’s barcode, or its SKU when it has no barcode, because scanning either one finds the product. The symbology is Code 128, which covers the printable ASCII range, so ordinary SKUs work as they are.

A product with neither a barcode nor a SKU is given an internal code in the form INV-000001 when you print, so the label that comes off the printer scans back to the right product. The dialog says how many products that affects before printing. A code containing characters Code 128 cannot encode prints without bars, and the dialog warns about that too.

Count sheets and order sheets

A stocktake in progress can print a count sheet: the frozen list with a blank column to write in, ordered by name or by shelf code, with the expected quantity omitted on a blind count. Its footer repeats the rule that a blank row is a skipped row, left untouched when the count is applied.

A reorder group prints an order sheet with quantity, unit, product, the supplier’s own code, and your SKU, headed with the supplier, the date, the number of lines, and their email address, and footed with their usual lead time. A saved count can be printed as a variance report with expected, counted, change, and value at cost.

Print a view as it stands

Products and Reports both have a Print button that prints the page as you have filtered it, with the navigation, buttons, and other app furniture stripped out by the print stylesheet. On a phone the product cards switch to the table first, because a table is what a document wants.

There is no built-in PDF export. Your browser’s own print dialog handles paper, printer selection, and saving to PDF, which it does better than a bundled library would.

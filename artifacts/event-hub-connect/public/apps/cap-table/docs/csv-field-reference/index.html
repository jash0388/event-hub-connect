CSV import field reference

Look up supported Cap Table CSV columns, required values, instrument-specific fields, formatting, and import limitations.

Puter·Product documentation·3 min read

Use the templates and review column mapping

Download the stakeholder or securities template from Settings → Import from CSV. The importer recognizes comma, semicolon, and tab separators from the header, and supports quoted fields containing separators or newlines. Verify the preview rather than relying solely on automatic matching.

Use explicit ISO dates such as 2026-09-09, whole share counts, and separate monetary and quantity columns. Percentage fields use percentage values, such as 20 for 20%. Amounts use the selected company’s currency.

Stakeholder columns

Stakeholder CSV fields
ColumnUse
NameRequired. Holder name used to match securities.
EmailOptional valid email address.
TypeHolder category, such as founder, investor, employee, advisor, or entity. Review the mapped result.

Import stakeholders before securities. Existing names and duplicate names can be skipped; check the preview’s reasons. If distinct entities have the same name, resolve the identity and naming in the source before relying on name-based matching.

Security columns

Security CSV fields
ColumnUse
Stakeholder; Security type; DateRequired. Match the holder; identify shares, options, RSUs, warrants, SAFEs, or notes; supply the event date.
Share class; QuantityClass name where applicable and the share or award quantity.
Price per share; Strike priceShare issue price or option/warrant strike, as applicable.
Principal; Valuation capConvertible principal and optional cap. These are monetary amounts.
Discount (%); Interest (%)Conversion discount and note simple-interest rate.
SAFE cap typePre-money or post-money SAFE basis.
Vesting (months); Cliff (months); Vesting startRegular vesting terms where applicable.
Expires; Maturity dateExpiration for relevant instruments; note maturity.
83(b) filedActual election filing date for relevant restricted stock.
PlanEquity-plan name for options/RSUs; use none for an award outside all plans.
Pro-rata rights JSON; MFN JSONOptional structured negotiated terms. See the section below.
Dividend events JSON; Economic basis JSONOptional dividend declarations and payments, and the original investment they accrue on, for a share certificate.

A blank Plan can resolve when exactly one plan is eligible; otherwise identify it explicitly. The preview can propose missing classes. Confirm their names and review their full terms after import.

Import and export negotiated financing terms

Four optional columns carry structured terms as JSON, in the shape the Export financing terms report writes from the Securities view. That report is the practical way to produce them: it lists every class with dated preferred terms and every security carrying rights, an MFN clause, dividend events, an economic basis, or financing evidence.

  • Pro-rata rights JSON and MFN JSON accept the recorded clause. MFN terms require a SAFE or note.
  • Dividend events JSON and Economic basis JSON require a share certificate.
  • Values are validated as strictly as a form entry. A clause the app cannot calculate fails its row rather than importing without the term, and the row reports the reason.
  • MFN elections are never imported. Import the clause, then record an election from the security sheet so the elected terms always come from an instrument on file.

The exported report is a review and transfer aid, not a restore format: it does not carry share classes, scenarios, or the source IDs an election refers to. Use a company JSON backup when you need a supported round trip. See Record SAFEs and convertible notes and Record preferred dividends for the terms themselves.

Know what a CSV does not restore

The CSV field set is not a complete company-backup format. It does not import attachments, the audit trail, custom vesting tranches, acceleration terms, a full exercise/settlement history, or every option classification field. Review those terms in the app after importing; use a company JSON backup for a supported round trip of company data.

Files are limited to 10 MiB and 10,000 data rows per import, with additional company limits. An import adds securities rather than replacing the cap table. Correct errors and review duplicate warnings before saving.
